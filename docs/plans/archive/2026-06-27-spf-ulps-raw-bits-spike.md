Determine whether Teralizer can exceed JARVIS on Precision-style ulps checks by making SPF preserve symbolic information through `Double.doubleToRawLongBits(double)`.

## Goal

Turn `Precision.equals(double,double,int maxUlps)` from a documented raw-bits concession into either a working SPF capability or a precisely bounded upstream-SPF implementation task.

## Resolved blocker

`Double.doubleToRawLongBits(double)` was dispatched through JPF's native peer `jpf-core/src/peers/gov/nasa/jpf/vm/JPF_java_lang_Double.java`. The core peer receives a concrete `double` parameter and returns `Double.doubleToRawLongBits(v0)`, so the symbolic attribute attached to the JVM stack slot was lost before the bit pattern reached symbolic long operations.

The spike adds a symbc-local peer at `jpf-symbc/src/peers/gov/nasa/jpf/symbc/JPF_java_lang_Double.java`. When the argument carries a `RealExpression`, it attaches a `RawDoubleBitsExpression` to the returned long; `PCParser` lowers that expression through `ProblemGeneral.fpToIEEEBV`, implemented for `ProblemZ3` and `ProblemZ3BitVector` with Z3's `mkFPToIEEEBV`.

This is not the same as `D2L`: numeric double-to-long conversion adds a numeric relation, while raw-bits reinterpretation needs IEEE-754 bit-vector semantics.

## Why this is worth a spike

SPF already has most of the required machinery:

- `symbolic.fp=true` switches Z3 real variables from rational `RealExpr` to IEEE-754 `FPExpr`.
- Z3's Java API provides `mkFPToIEEEBV(FPExpr)`, the exact `double -> 64-bit bit-vector` reinterpretation needed for raw bits.
- jpf-symbc already has symbolic long bitwise operations (`LAND`, `LXOR`, `LOR`, `LSHL`, `LSHR`, `LUSHR`) backed by Z3 bit-vectors.
- `ProblemZ3BitVector` already mixes FP and bit-vector sorts in other operations.

The spike is therefore an SPF integration task, not a new solver-research project.

- [x] Add an explicit JPF config path for the spike that sets `symbolic.fp=true`, `symbolic.bvlength=64`, and a negative `symbolic.min_double` bound so negative doubles are not made UNSAT by the current default lower bound.

- [x] Add a symbc-local `java.lang.Double` native peer override for `doubleToRawLongBits__D__J` that, when the argument has an FP symbolic attribute, returns a long with the `fpToIeeeBv` bit-vector expression attached; otherwise it preserves the concrete JPF behavior.
- [x] Run the failing SPF test again and confirm that downstream long bitwise operations receive a symbolic bit-vector expression.
- [x] Add a pinned Commons Math `Precision.equals(double,double,int maxUlps)` spike fixture only after the raw-bits unit test passes.

## Result

`TestDoubleRawBits` now covers both levels of the SPF implementation:

- `rawSignMatchesDoubleSign(sym)` verifies the returned raw long carries a symbolic bit-vector through sign-bit masking.
- `precisionLikeMaxUlps(sym)` mirrors the Commons Math `Precision.equals(double,double,int maxUlps)` raw-bits branch and verifies SPF explores both the in-range and out-of-range ulps paths.
- `rawBitsConcreteFallback(sym)` verifies the peer remains a concrete fallback in default rational-real mode unless `symbolic.fp=true` is enabled.

The pinned Commons Math fixture now also includes `JarvisMathScorecardTest.precisionEqualsMaxUlps`, generated by `scripts/prepare-jarvis-scoreboard-fixtures.sh`.

## Related SPF cleanup discovered by the spike

- Fix `MinMax`'s default double lower bound (`Double.MIN_VALUE` is the smallest positive nonzero double, not a negative bound) or make Teralizer emit an explicit negative `symbolic.min_double` in generated JPF configs.
- Inspect `LUSHR`'s double-assignment branch. It is not expected to block `Precision.equals(..., maxUlps)`, but it is a real symbolic-bytecode correctness bug if the overwritten branch is reachable.
- Keep `FastMath.abs` model-class work separate. Model classes express branch-equivalent Java methods; they cannot express `doubleToRawLongBits` bit reinterpretation.

## Acceptance criteria

- A symbolic raw-bits unit test distinguishes at least two input regions that previously collapsed under the concrete native peer.
- The implementation is guarded so default rational-real runs are unaffected unless `symbolic.fp=true` is enabled.
- The spike records that a `Precision.equals(double,double,int maxUlps)` fixture and equivalent unit-test branch can produce path conditions over the ulps branch.
- The JARVIS scorecard audit records the pure maxUlps fixture as a separate, non-Table-2 probe instead of conflating it with the existing eps fixture.
