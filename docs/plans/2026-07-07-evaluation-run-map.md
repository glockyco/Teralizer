# Evaluation Run Map

Which measurement feeds which research question, at which corpus, variants, and
phases. RQ1--RQ6 were already evaluated in the past; **this evaluation adds the new
RQ0 and refreshes RQ6**. Design authority for the paper's RQ text is
`~/Projects/test-generalization-paper/sections/04-evaluation-*.tex`; for RQ0,
`2026-06-30-jarvis-comparison`.

## Research questions (paper numbering — authoritative)

- **RQ0** *(new)* — comparison against JARVIS.
- **RQ1** — how much generalization improves the mutation score of existing suites.
- **RQ2** — how constraint complexity affects constraint-aware vs random input generation.
- **RQ3** — how generalization affects target-suite size and runtime.
- **RQ4** — efficiency of generalization vs test generation (EvoSuite).
- **RQ5** — causes of unsuccessful generalization under controlled conditions.
- **RQ6** — causes of unsuccessful generalization under real-world conditions.

## Datasets (three, plus one naming trap)

- **EqBench** — 652 numeric-focused classes; tests generated by EvoSuite at three
  budgets (1s/10s/60s → variants Es1/Es2/Es3). Controlled conditions.
- **Apache Commons utility methods ("commons-utils")** — 247 *extracted public-static
  numeric/boolean methods* from 17 Commons projects (+ transitive deps, ~19.7k LOC);
  EvoSuite tests at three budgets **plus** a developer-test variant (725 original tests).
- **RepoReapers** — 1,161 real-world GitHub Java projects, of which 611 are checked
  out, resolved, and built, and therefore carry results.

**Naming trap:** "Apache Commons" means two different corpora. RQ1--RQ5 use the
*extracted utility methods* above. **RQ0 uses the full original Commons projects that
JARVIS evaluated** (whole test suites), not the extracted methods. Do not conflate them.

RQ1--RQ5 are **not** re-run here; they stand from the prior evaluation on
`postgres_dev`. The prior eval used the nine-variant scheme (BASELINE + NAIVE and
IMPROVED at 10/50/200 tries); RQ0 uses IMPROVED at 100/200/1000 (NAIVE dropped from
the RQ0 lane per the 2026-07-06 variant policy in `2026-06-30-jarvis-comparison`).

Scoreboard runs all phases because its PVC/mutation-score numbers are the point and
its scope is narrow (cheap). Census and rerun3 run generalization first to prove
Stage-4 applicability before any mutation spend; a reduction pass follows, sized per
project (math alone needs hours — `2026-07-05-concretization-census-findings`).

## Shared data primitives

- `generalization` + `jqwik_property_execution.diagnostic_kind = 'FULL'` — sound generalizations (applicability numerator).
- `filter_result.reason_code` — the funnel: why each test / assertion / generalization drops. Compile-based quarantine now writes a row here with the javac error as `reason` (previously invisible). This is the core RQ6 dataset.
- `jacoco_coverage_report` — IC. `pit_coverage_report` / `pit_mutation_report` — covered mutation score / kills (PVC and RQ0 Axis 2 come from here).
- `v_projects_generalized` vs `v_projects_reduced` — Stage-4 applicability reported independently of whether Stage-5 mutation ran.
