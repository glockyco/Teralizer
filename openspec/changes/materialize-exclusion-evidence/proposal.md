## Why

The registered RQ6 report preserves collapsed headline results, but it does not materialize the
five-mechanism exclusion partition, the complete attempt-to-final-usable funnel, or the denominators
needed by the thesis's retained RQ6 claims. Some causal explanations survive only in retired prose or
ad hoc queries and must either gain reproducible evidence or be discarded.

The fix is durable empirical output, not a permanent bureaucracy for deleting documents. One focused
migration audit is still required because the six retired sources are the only checklist of claims that
may have lost an owner.

## What Changes

- Perform one **claim-level migration audit** of the six sources removed by
  `consolidate-repository-knowledge`. Use historical prose only as a checklist. For each substantive
  claim, record a maintained owner, reproducible evidence, a stale/disproved disposition, or a deliberate
  discard. Store the completed audit with this change and archive it with the change; do not add a
  runtime retirement ledger or permanent repository-validation subsystem.
- Materialize the RQ6 five-mechanism exclusion partition and denominator funnel as typed,
  provenance-bearing report outputs.
- Keep one executable mechanism mapping and shared vocabulary. Build separate typed relations for the
  project, test, assertion, filter-adjudication, and generated-generalization evidence that actually
  exists; do not force all entity levels into one physical row shape.
- Make the semantic collapse explicit: filter rejection, pre-emission refusal, and unsupported
  capability are filtering outcomes; build quarantine and task failure are failures.
- Define filter adjudication so quarantine rows that share the `filter_result` storage shape are not
  misclassified. Expose distinct attempted, emitted, adjudicated, filter-passed, validated, reduced,
  and final-usable measures where independent evidence exists.
- Materialize only the mechanism, funnel, denominator, and comparison quantities that the downstream
  thesis claim inventory confirms as retained. Do not turn every current macro, table cell, or prose
  literal into a new metric.
- Keep metric-local metadata to semantic key, raw value, value kind, population, optional denominator
  key, and the existing code-provenance reference. Resolve corpus identity and repository-file input
  revisions through the owning report run's input snapshots and provenance manifest.
- Preserve fail-loud behavior for unknown exclusion codes, record shapes, non-filter producers, and
  reconciliation mismatches.
- Inventory the causal explanations that remain after persisted codes and focused fixtures are applied.
  Create a deterministic registered audit input only if a surviving explanation still requires human
  interpretation; otherwise record that no qualitative audit is required.
- Correct source comments and diagnostics that contradict current classification without changing
  scheduling, frozen corpus rows, or measured entities.
- Consume the corpus registry, explicit report-run architecture, typed table model, and declaration-
  driven publication path. Add no parallel runner, manifest, renderer, or consumer copy step.

## Capabilities

### New Capabilities

- `reporting/exclusion-evidence`: typed and denominator-explicit RQ6 mechanism and funnel evidence,
  retained citable quantities, conditional causal audit evidence, and fail-loud reconciliation.

### Modified Capabilities

None. `reporting/exclusion-accounting` and `pipeline/cross-stage-contracts` come from
`consolidate-repository-knowledge`. This change consumes those accepted semantics and materializes
reader-facing evidence without restating their classification ownership.

## Impact

- RQ6 report modules and typed evidence helpers; retained registered metrics, LaTeX, CSV, markdown,
  provenance, and focused corpus-backed invariants.
- A versioned deterministic audit input and registered summary only if surviving causal claims require
  reviewer interpretation.
- `consolidate-repository-knowledge` remains the completed owner of repository authority and exclusion
  accounting. It is not reopened and no second knowledge-retirement capability is created.
- `consolidate-evaluation-databases` supplies semantic corpus identity and prepared read-only inputs.
- `make-report-runs-explicit`, `separate-report-values-from-presentation`, and
  `declare-published-artifacts` supply the run, rendering, and delivery contracts.
- The thesis receives no hand-maintained number and no manual copy. `reconcile-reporeapers-claims`
  consumes the finalized declared artifacts in one later thesis migration.
- No pipeline scheduling, exclusion decision, frozen database row, measured entity, or Git history is
  rewritten.
